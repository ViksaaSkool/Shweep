# Monetization runbook (future feature)

This document describes the **optional, currently disabled** monetization stack:
a RevenueCat "Unlimited Sheep" lifetime purchase plus a Firebase-backed
cross-device daily sheep quota.

> Status: **not enabled**. The shipping app contains no RevenueCat/Firebase
> code, dependencies, configuration, keys, or network activity. Everything here
> only takes effect for builds that opt in with
> `-Pshweep.monetization.enabled=true`.

## Isolation model

| Layer | Current build (`false`) | Monetized build (`true`) |
|---|---|---|
| RevenueCat SDK | not resolved | `:monetization` module |
| Firebase SDK | not resolved | `:monetization` module |
| `google-services.json` / `GoogleService-Info.plist` | absent | generated by CI |
| Public API keys | absent | generated/read at runtime |
| Sign-in | none | Google (Android) / Apple (iOS) |
| Daily quota | unlimited | enforced by backend |
| Purchase UI | hidden | shown in Settings |

Enforcement:

```sh
python3 tools/monetization_guard.py check-source
python3 tools/monetization_guard.py check-config
python3 tools/monetization_guard.py check-archive <apk|aab|.app>
python3 tools/monetization_guard.py self-test
```

`.github/workflows/monetization-boundary.yml` runs these on every push/PR,
including a check that the resolved dependency graph contains no
RevenueCat/Firebase.

## Do I need API keys and configuration?

Yes. For the future monetized build you need **platform configuration and public
client keys**. None of these belong in the repository.

### RevenueCat (client, public SDK keys)

| Value | Used by |
|---|---|
| `REVENUECAT_ANDROID_PUBLIC_KEY` (Google, `goog_...`) | Android build |
| `REVENUECAT_IOS_PUBLIC_KEY` (Apple, `appl_...`) | iOS build |

- Public SDK keys are not secrets; they are expected to be recoverable from the
  compiled app. They are still generated from CI secrets to avoid repository
  churn and accidental Test Store key leakage.
- Never embed a RevenueCat secret key (`sk_...`) in the app.

### Firebase (client configuration)

| Value | Used by |
|---|---|
| `FIREBASE_ANDROID_CONFIG_BASE64` → `google-services.json` | Android build |
| `FIREBASE_IOS_CONFIG_BASE64` → `GoogleService-Info.plist` | iOS build |
| `GOOGLE_AUTH_WEB_CLIENT_ID` | Google Sign-In (Android) |

### Backend secrets (server only, Firebase Secret Manager)

| Value | Used by |
|---|---|
| `REVENUECAT_SECRET_API_KEY` | RevenueCat customer lookup in the webhook |
| `REVENUECAT_WEBHOOK_AUTH` | Webhook authorization header |

### Store credentials (dashboards only)

- Google Play service-account JSON → RevenueCat.
- App Store Connect In-App Purchase `.p8` key, key id, issuer id → RevenueCat.

All of the above are already listed in `.gitignore`.

## Build commands

Current (production) build — unchanged, safest:

```sh
./gradlew :composeApp:assembleRelease
```

Future monetized build:

```sh
./gradlew :composeApp:assembleRelease -Pshweep.monetization.enabled=true
```

With the flag off, `settings.gradle.kts` never includes `:monetization`, so no
RevenueCat/Firebase dependency is resolved.

## GitHub environments

Create `monetized-development` and `monetized-production`.

Development secrets:

```
REVENUECAT_ANDROID_TEST_KEY
REVENUECAT_IOS_TEST_KEY
FIREBASE_ANDROID_TEST_CONFIG_BASE64
FIREBASE_IOS_TEST_CONFIG_BASE64
GOOGLE_AUTH_TEST_WEB_CLIENT_ID
```

Production secrets (protect the environment with required approval):

```
REVENUECAT_ANDROID_PUBLIC_KEY
REVENUECAT_IOS_PUBLIC_KEY
FIREBASE_ANDROID_CONFIG_BASE64
FIREBASE_IOS_CONFIG_BASE64
GOOGLE_AUTH_WEB_CLIENT_ID
```

CI decodes config only for monetized jobs, e.g.:

```sh
printf '%s' "$FIREBASE_ANDROID_CONFIG_BASE64" | base64 --decode > composeApp/google-services.json
printf '%s' "$FIREBASE_IOS_CONFIG_BASE64" | base64 --decode > iosApp/iosApp/GoogleService-Info.plist
```

Never build a **production** release with a Test Store key.

## Product model

- Purchase: lifetime non-consumable.
- Entitlement id: `unlimited_sheep`.
- Store product id: `unlimited_sheep`.
- Daily limit (when not entitled): 50 sheep.
- Reset boundary: 12:00 UTC.
- Identity: Firebase UID is the RevenueCat `appUserId`.
- Installation id: random UUID generated on first launch (`installationId`,
  never a hardware/device identifier).

Always unlock from:

```kotlin
customerInfo.entitlements["unlimited_sheep"]?.isActive == true
```

## Activation sequence

1. Create the RevenueCat project and connect the Google/Apple apps.
2. Create the `unlimited_sheep` entitlement, `default` offering and packages.
3. Create the Firebase project; enable Google and Apple auth providers.
4. Deploy the backend (`backend/`), rules, and webhook.
5. Add the CI secrets to the monetized environments.
6. Implement the `:monetization` gateway/client (see
   `monetization/README.md`) against the existing `StorePurchaseGateway` seam.
7. Build with `-Pshweep.monetization.enabled=true` and test in store sandboxes.
8. Update the Privacy Policy, Terms, and store data disclosures.
9. Ship with the flag **off**, then enable in a later reviewed build.

## Backend data

Authoritative quota and entitlement state live in Firestore and are written
only by Cloud Functions (see `backend/`). The client cannot write to
`entitlements`, `quotaPeriods`, or `quotaRequests`.

## Known trade-offs

- Anonymous cross-platform purchase sharing is intentionally **not** supported;
  restoration is same-store-account per platform unless a shared identity is
  introduced later.
- Cross-device quota requires sign-in.
- Offline consumption uses a local cache and an idempotent sync queue; two
  offline devices may briefly exceed the shared quota before reconciling.
